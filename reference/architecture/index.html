Architecture

Crates

Dependencies point downward: roxy → roxy-proxy, roxy-http, roxy-rules, roxy-tls, roxy-wasm, roxy-node; roxy-proxy → roxy-http, roxy-tls, roxy-rules, roxy-wasm, roxy-log, roxy-state; roxy-rules, roxy-wasm, roxy-tls → roxy-http; roxy-node → roxy-state. roxy-http, roxy-log, roxy-addon and roxy-state depend on no other roxy crate; roxy-node-spec is tests-only. roxy-http and roxy-rules do no network I/O and are unit-tested and fuzzed directly.

crateresponsibility
roxyThe binary: CLI (run, check, ca, rule test, health), config loading and validation, secrets, address-list loading, reload, store wiring.
roxy-proxyListeners, connection state machines, exchange core, addon stack (including service layers), watcher, upstream connector and address floor, WebSocket relay, flow-log events and capture.
roxy-httpCanonical request/response model, strict HTTP/1.1 codec, h2 ↔ canonical mapping, URL normalisation, body framing with caps, content-coding decoders, WebSocket handshake checks and frame codec. No I/O policy.
roxy-tlsCA generation and persistence, leaf minting and cache (keyed on the canonical Host), rustls configs, ClientHello sniffing.
roxy-rulesExpression DSL (lexer, parser, type checker, compiler), policy evaluation, actions, metric and state stores.
roxy-wasmwasmtime component host for WASM addons: linking, capabilities, budgets, instance pools.
roxy-logBuffered single-writer log destinations: one writer thread, batching, backpressure, rotation, compression. Knows bytes, not events.
roxy-addonSDK for Rust addon authors: generated WIT bindings and wrappers.
roxy-nodeNode side of the control-plane protocol: enrolment and renewal, lease loop, flow spool and shipper. Knows nothing of the proxy; roxy applies leases through a handler.
roxy-stateThe state dir: its layout (node token, flow sequence, CA dir, quarantine marker) and the atomic writer the files it replaces (token, flow sequence, marker) go through. The CA dir's files are created once, never replaced, by roxy-tls.
roxy-node-specThe node protocol's OpenAPI document (spec/node-protocol/v1/openapi.yaml) with validators for its body schemas, for tests.
wit/The roxy:addon WIT package: the language-agnostic addon contract.

unsafe is forbidden in every crate except the generated bindings modules of roxy-wasm and roxy-addon (wit-bindgen and wasmtime::bindgen! output).

Glossary

  • Exchange / flow: one request and its response (or one WebSocket session) within a client connection. Each has a ULID.
  • Canonical: roxy's validated, normalised, version-agnostic HTTP model.
  • Admission rule / in-flight rule: decided before the request is forwarded (can allow or deny) versus re-checked as the exchange streams, reading values known only then (can only deny or add effects).
  • Policy: a compiled, immutable snapshot of the config, swapped atomically on reload.
  • Layer: one addon in the stack.
