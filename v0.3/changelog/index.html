Changelog

User-facing changes in each release, newest first. Each release has a short summary; expand it for the itemised entries, where breaking changes come first. Each release's GitHub page lists every merged pull request.

0.3.0 (2026-10-15)

Addons can now answer early and hold a request or response for approval, with the request and response lanes of an exchange living independent lives. This is a breaking change for addons: the service protocol is roxy.layer.v6 and the WASM interface is roxy:addon@0.3.0.

Details

Breaking

  • The service layer protocol is roxy.layer.v6. It is incompatible with roxy.layer.v5 and the experimental roxy.layer.v0, and roxy does not accept a v5 peer: both sides must handle stop, trailers, explicit ends in both directions and headless completion. The bundled Python helper implements the new contract (#558).
  • The WASM addon interface is roxy:addon@0.3.0. Components built against 0.2.x or the unversioned package must be rebuilt with the matching SDK and WIT (#558).

Added

  • An addon can answer before forwarding, hold a request or an upstream response while it decides, and stream approved content into an answer it has already started. An approval addon can send 200 text/event-stream with keepalive comments while it holds a request or a tool-call event, then approve, edit or deny it (#558).
  • The request and response lanes of an exchange have independent lifetimes: a layer can end or stop one without the other, and an upstream head that arrives after an early answer is still delivered to the addon (#558).
  • Trailers pass through service layers and WASM host-side passthrough, so gRPC status trailers survive an addon stack. WASM byte-stream rewriting has no trailer API and the Python forwarding helpers do not send trailers (#558).

Changed

  • Upstream informational responses such as 103 Early Hints are discarded, with or without addons, and an addon cannot publish an informational head (#558).

  • A WebSocket upgrade reserves its relay resources before the 101 reaches the client (#558).

  • Publishing a second outgoing head on a lane is a layer failure and cuts an answer already in progress (#558).

  • A layer that fails while handling a core denial may produce a 503, but the flow record keeps the original deny rule and reason; the layer fault gets its own event (#558).

  • The final flow record for an exchange waits for both lanes' bodies, their validation and every accepted host call to finish (#558).

  • A body that streams through a layer costs more CPU per byte than it did; the fixed cost of a layer is unchanged. Tracked in #561.

Security

  • rustls 0.23.46 (RUSTSEC-2026-0346 to 0349) and wasmtime 49.0.3 (RUSTSEC-2026-0352 to 0364) (#557).

0.2.0 (2026-10-14)

Quarantine, a bearer-token node protocol, host services for service layers and X-Forwarded-For support, plus two security fixes (GHSA-4297-w88p-8xqv, GHSA-pwq9-p79h-pg35). Breaking for control planes, service layers (roxy.layer.v5), client.port users and the per-addon state store.

Details

Breaking

  • Node protocol: a node's credential is a rotating bearer token instead of a client certificate. Enrolment returns token, not_after and renew_after_seconds; later requests send Authorization: Bearer; the state dir holds node.token in place of node.crt and node.key. A control plane built for mutual TLS no longer works (#528).
  • The service layer protocol is roxy.layer.v5: the open message carries the layer's grants and config, and a service may send host-service calls on its stream (#526).
  • client.port is removed as a rule field and metric key. The flow log keeps the TCP peer as client.peer: { ip, port }, so client.port moves to client.peer.port in the log (#525).
  • The per-addon state store and the addons[].state block are gone: a WASM layer's state-get and state-put use the store the rules read with state[..], sized by limits.max_state_entries. A state-put without a TTL gets one hour, not six (#511).
  • Stricter YAML: yes, no, on and off are not booleans, << merge keys and custom tags are errors, and a file holds one document (#482).

Added

  • Quarantine: a rule's quarantine action or a listener's quarantine_on.parse_errors threshold puts the proxy into a durable state where every exchange is refused 403 _quarantined. The trip is written to <state-dir>/quarantine and survives a restart; an operator removes the marker, or in node mode the control plane names the incident in the lease's quarantine.release list. roxy run --config accepts --state-dir, required when the config uses quarantine (#505).
  • A layer of either kind can quarantine the proxy through the new quarantine capability: flow.quarantine for WASM, a quarantine message for a service (#529).
  • Service layers get the host services WASM layers have: log, record, add_tag, state_get, state_put and metric_get messages, each answered with a result; capabilities and config are accepted on a service layer (#526).
  • An http listener takes forwarded_for: { trusted_hops: N } to recover the client IP from X-Forwarded-For; the result is client.ip everywhere. A header with too few entries or a malformed trusted entry is refused 400 forwarded_for_invalid. The setting is a config error on an http_proxy listener (#525).
  • Node protocol: the lease poll reports seq_unreserved when the node could not persist its flow sequence counter (#502).
  • The docs site publishes each release under /vX.Y/ with a version menu (#522).

Changed

  • The rule language calls a field admission when it is known at the forwarding decision and in-flight when it is re-checked as the exchange streams, in place of "head" and "watched"; roxy check, rule test and the compiler diagnostics use the new words (#524).
  • A tag an enforce layer adds is visible to tag[..] in admission and in-flight rules and to the when of the layers below; the 64-tag / 4 KiB cap now counts the rules' tags too (#534).
  • The wait for a busy layer instance is bounded by the layer's first_byte_timeout; past it the exchange fails closed with layer_error kind no_instance (#513).
  • The health and CA listener has its own connection cap, so a client filling limits.max_connections on the proxy port cannot starve /healthz (#503).
  • roxy check warns about a metric keyed on host or client.port without a where, with field-specific advice, and no longer warns for unique(..) fields (#497).
  • The WIT package is roxy:addon@0.2.1, an additive bump that 0.2.0 components still load. The SDK's flow::metric_get loses its key parameter (#542).
  • Node mode: a 401 on /renew is retried with backoff rather than ending renewal; 410 or 426 at enrolment is reported as a refusal (#546).
  • A service observe stream ends on the service's last message rather than roxy's, with first_byte_timeout to send it, so a service observer can read a body and then record. Host calls queued before a stream ends still run (#548).
  • A layer's own body that is still open splices the bypassed body as unknown length, so a held-back end or a failure is always a visible cut. A head-only WASM request layer that passes a stream to next now sends a chunked request upstream (#543).
  • The node reserves flow sequence numbers off the emit path, so a slow disk no longer stalls every emitter (#485).

Fixed

  • A WebSocket through a layer subscribed to (request: full, response: head) no longer stalls (#516).
  • A service-layer head with too many header fields is refused at limits.max_headers instead of panicking (#499).
  • Client parse-error detail is redacted in the operational log as it is in the flow log (#498).

Security

  • GHSA-4297-w88p-8xqv: Host: [::ffff:1.2.3.4] bypassed a deny on 1.2.3.4. An IPv4-mapped IPv6 literal now parses as the IPv4 address it embeds, and a host or tls.sni literal written in the mapped form is a compile error (#506).
  • GHSA-pwq9-p79h-pg35: with http.allow_obs_text: true, a header value holding a byte of 0x80 or above was invisible to an equality rule but forwarded. Rules now read header values as the bytes that are forwarded, one character per byte (#507).
  • YAML is read with serde-saphyr; the unmaintained unsafe-libyaml (RUSTSEC-2024-0449) is gone (#482). ruzstd 0.9.1 for RUSTSEC-2026-0344 (#505).

0.1.1 (2026-10-12)

Heads cross the WASM boundary as records and bodies as bare streams (roxy:addon@0.2.0), layers subscribe to only the directions they need, and a batch of host hardening fixes. Breaking for WASM components and service layers (roxy.layer.v4).

Details

Breaking

  • The WASM addon interface is roxy:addon@0.2.0: a head crosses the guest boundary as one record per direction and bodies are bare wasi:io streams; the wasi:http import is gone. Components must be rebuilt against SDK 0.2.0, which is source-compatible (#424).
  • The service layer protocol is roxy.layer.v4: the deny message is gone (a service refuses by answering with a response) and open carries the layer's subscription (#420).
  • Removed audit_endpoint, the audit flag of flow.record, endpoint retries and the attempts field of the endpoint_call event (#420).
  • Removed the dead transparent-listener keys (mode: transparent, allow_passthrough, upstream_target); they are now unknown-field errors (#457).
  • A host or tls.sni literal that can never match (trailing dot, non-ASCII, bracketed IPv6) is a compile error with a rewrite hint (#463).

Added

  • A layer declares what it wants of each direction with subscribe: { request: head | full, response: head | full }. A body a layer is not subscribed to bypasses it; bytes it passes on for that body fail the exchange closed (#420).
  • SECURITY.md, pointing at private vulnerability reporting (#464).

Changed

  • first_byte_timeout is one budget per head, request and response alike, for WASM layers as it already was for service layers (#431).
  • Service layer streams spread across up to max_connections connections instead of filling one, and writes are flushed in batches (#423).
  • The addon SDK moves bodies and heads a layer does not touch host-side, cutting a no-op layer's cost (#418).
  • A fault after the response head carries its own reason into the request event (buffer_budget_exhausted, upstream_body_failed, layer_error or the client's parse reason) instead of response_write_failed (#419).
  • like patterns are capped at 1 KiB and compiled with the same limits as matches; ? matches one character, as documented (#459).

Fixed

  • A guest head with tens of thousands of header fields is refused at limits.max_headers instead of panicking the host (#458).
  • A guest that writes to stdout or stderr no longer fails every exchange through its layer (#469).
  • A handler that returns without responding is treated like a trap: the instance is discarded and the exchange fails (#460).
  • An endpoint call waits for its in-flight permit before its body leaves the guest (#465).
  • A service connection whose write side has died fails its exchanges at once with service:closed instead of after first_byte_timeout (#461).
  • Body frames on an ended service stream are dropped without crediting, so a misbehaving service cannot grow roxy's memory (#462).
  • response_body_idle_timeout applies while a response body is collected for inspection; a stalled upstream under a body rule gets a 504 (#467).
  • The reference says what the code does where it overclaimed: timeouts, drain and linger limits, the hop-by-hop list, node 410 handling and lease fields (#457); HTTP/1.0 close-delimited responses are documented (#466).

0.1.0 (2026-10-08)

The first release: a strict, programmable HTTP firewall.

  • Two ways to deploy it: as an egress proxy for a workload you don't trust (mode: http_proxy, with TLS terminated by roxy's own CA), or as a gateway in front of the APIs your clients call (mode: http).
  • One canonical form: every request is parsed into one strict model and re-serialised, over HTTP/1.1 and HTTP/2, with WebSockets relayed. Anything roxy cannot parse, verify or classify is denied.
  • A typed YAML rule language where deny always wins and nothing unlisted passes; rules can watch bodies and WebSocket messages as they stream. Metrics give rate limits and byte budgets; secret injection and AWS SigV4 signing mean clients hold only placeholders.
  • Addons above the rules, as WASM components in process or external services streamed over WebSocket: they can rewrite, withhold, answer or block, and the rules judge whatever they pass on.
  • A JSONL flow log naming the rule or addon behind every decision, with optional body capture and digests; backpressure holds traffic until the log catches up.
  • Node mode: roxy enrols with a control plane, leases its policy and secrets into memory, and ships its flow log.
