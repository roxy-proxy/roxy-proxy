# Overview

roxy is an HTTP firewall and egress proxy for workloads you don't fully trust. Clients use it as an explicit `HTTP_PROXY`, or reach it through its own DNS if they ignore proxy settings ([DNS steering](/deploy/dns-steering)). It decides what each request may reach, holds the credentials the workload needs so the workload never sees them, and logs every decision as a line of JSON.

Every exchange takes the same path: roxy decrypts it, the addons see it, the rules judge it, and the connector dials the upstream. The response comes back the same way in reverse.

## Decrypt

roxy terminates TLS with certificates from its own CA and parses each request into one canonical form, which is what it sends upstream. Ambiguous input is rejected, not guessed at. Request smuggling and header injection don't reach the upstream, and what the rules and addons see is exactly what is forwarded ([HTTP](/reference/http)).

## Addons

Logic that needs to understand the traffic goes in an addon: an external service that the traffic streams through, or a WASM component that runs in process. An addon owns both streams of the exchanges it chooses. It can rewrite, withhold, answer or block. Here a sentinel runs as a sidecar and holds each of an agent's model calls until it has judged it, and a second addon gets a copy of one write in ten for an external audit service:

```yaml
addons:                                    # above the rules, outermost first
  - name: sentinel                         # a sidecar the exchange streams through
    kind: service
    when: host == "api.anthropic.com" and path starts_with "/v1/messages"
    endpoint: sidecar
    endpoints:
      sidecar: { url: "http://sentinel:9000/", private_ok: true }
    limits:
      first_byte_timeout: 120s             # how long it has to decide before roxy denies

  - name: audit-tap                        # sent a copy; can't change or delay traffic
    kind: service
    mode: observe
    when: method in [POST, PUT, PATCH, DELETE]
    sample: 0.1
    endpoint: tap
    endpoints:
      tap: { url: "https://audit.internal/roxy", private_ok: true }
```

Whatever `sentinel` passes on is still judged by the rules. If it fails, the flow is denied. [Addons](/addons/overview) covers the model, [service layers](/addons/service-layers) the protocol, and [writing one](/addons/writing) the WASM SDK.

## Rules

The rules are a list of allows plus the denies that restrict them, in one YAML file. A matching deny always wins, and anything no rule allows is denied. Rules read the request head, and they can keep watching the bodies and the response as they stream. Metrics give you rate limits and byte budgets.

```yaml
secrets:
  openai: { env: OPENAI_API_KEY }

rules:
  - id: github-reads
    when: host under "github.com" and method in [GET, HEAD]
    then: allow

  - id: openai
    when: host == "api.openai.com" and path starts_with "/v1/" and method == POST
    then:
      - set_header: { authorization: "Bearer ${secret:openai}" }   # the client never sees the key
      - allow

  - id: upload-cap                         # watches the body as it streams
    when: host == "api.openai.com" and body.bytes > 10mb
    then: { deny: { status: 413 } }
```

You can try a policy without sending traffic:

```sh
roxy rule test --config roxy.yaml POST https://api.openai.com/v1/responses
```

The full language is in [rules](/reference/rule-language). Past the rules, the connector resolves the host itself and checks the address it actually dials, so a name that resolves somewhere private is refused ([address floor](/policies/address-lists#address-floor)).

## Log

Every stage writes to the flow log: one JSON line per exchange, naming the rule that decided, the addons that ran and what changed. The log never drops a record. When it falls behind, traffic waits ([flow log](/operate/flow-log)).

It fails closed. If roxy can't parse, verify or classify something, it denies it. A broken config is not loaded, a failing addon denies the flow, and a missing metric or secret denies rather than allows.

## Use cases

- [AI agents](/use-cases/ai-agents): allow the model APIs and source hosts an agent needs, inject provider keys at the boundary, cap uploads and rate-limit writes.
- [CI jobs](/use-cases/ci): read-only access to the registries a build needs, no route anywhere else, a log of every fetch.

## What roxy is not

roxy is not a transparent gateway. It decides what passes through it, and it can't stop traffic that never reaches it. To contain a workload, the network has to give it no route out except through roxy. [Containing a workload](/deploy/overview) gives the recipe.

roxy speaks HTTP/1.1, HTTP/2 and WebSockets to clients. Raw TCP doesn't pass. The [principles](/principles) page sets out the threat model: what roxy prevents and what it doesn't try to prevent.
