# Quickstart

Run Claude Code through roxy, with an [inspect_sentinel](https://github.com/meridianlabs-ai/inspect_sentinel) sidecar that judges every tool call before Claude Code sees it. By the end, Claude Code works as usual, except that tool calls matching a denylist are blocked, and every request it makes is in roxy's flow log. The setup is [`examples/quickstart`](https://github.com/roxy-proxy/roxy-proxy/tree/main/examples/quickstart) in the roxy repo.

## Prerequisites

- Docker with Docker Compose
- Git
- [Claude Code](https://code.claude.com/docs/en/overview), signed in or with `ANTHROPIC_API_KEY` set

::::steps
### Clone the repo

```sh
git clone https://github.com/roxy-proxy/roxy-proxy.git
cd roxy-proxy/examples/quickstart
```

### Start roxy and the sentinel

```sh
docker compose up -d --wait
```

The first run builds the sentinel image, which takes a minute or two. Three containers start:

- **roxy**: the proxy on `127.0.0.1:3128`. It generates its CA on first start and serves the certificate on `127.0.0.1:3130`.
- **sentinel**: the inspect_sentinel sidecar, on a network with no route out. Every exchange streams through it. It runs a denylist over tool calls.
- **inspect-view**: Inspect's log viewer on `127.0.0.1:7575`, showing each conversation and the sentinel's verdict on every tool call.

### Trust roxy's CA

roxy terminates TLS with certificates from its own CA, so Claude Code has to trust that CA:

```sh
curl -fsS http://127.0.0.1:3130/roxy-ca.pem -o roxy-ca.pem
```

### Run Claude Code through roxy

```sh
HTTPS_PROXY=http://127.0.0.1:3128 \
NODE_EXTRA_CA_CERTS=$PWD/roxy-ca.pem \
CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1 \
claude
```

`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` turns off telemetry and error reporting, whose hosts the policy doesn't allow.

### Ask for something the denylist blocks

Ask Claude to fetch a page with curl:

```
> Use curl to fetch https://example.com
```

The model answers with a Bash tool call that runs `curl`. The sentinel sees it before Claude Code does, takes the tool call out, and puts a note in its place:

```
roxy's sentinel blocked a Bash tool call (denylist match: 'curl').
```

Claude Code never ran the command. Its turn ends, and you can carry on. Tool calls that don't match work as usual.

### Watch it in Inspect View

Open [http://127.0.0.1:7575](http://127.0.0.1:7575). Each Claude Code conversation is a sample. Its transcript shows every model call, the tool calls the model asked for, and the sentinel's verdict under each one: `Continued`, or `Rejected` with the reason. Reload the page to see new calls.

<img src={inspectView} alt="Inspect View: Claude Code's curl tool call, and the sentinel's rejection under it" />

### Read roxy's flow log

```sh
docker compose logs roxy
```

roxy's flow log has a line for every request Claude Code made, model calls or not, with the rule and the addons each one went through. Each sample in Inspect View lists the flow ids of its model calls (Metadata tab), so the two join. To keep whole requests and responses too, turn on [capture](/operate/flow-log#capture).

### Clean up

```sh
docker compose down -v
```

## What just happened

### Two layers

roxy decides by **host**. The policy allows Anthropic's API and sign-in hosts and denies everything else. That covers everything Claude Code sends through the proxy, not only its model calls: the commands it runs (a `curl` that got past the sentinel, `git`, `npm`) and WebFetch get a `403` from roxy for any other host.

The sentinel decides by **content**. It is a [service layer](/addons/service-layers): an addon that every exchange streams through, above the rules. It judges only model calls (`POST …/v1/messages`, or `…/chat/completions`), and passes every other request through untouched for the rules to decide. For each model response, it turns every tool call into an inspect_sentinel `BeforeToolCall` step and runs the configured sentinel on it. Whatever it passes on, roxy's rules judge again.

```yaml
addons:
  - name: sentinel
    kind: service
    endpoint: sidecar
    endpoints:
      sidecar: { url: "http://sentinel:9000/", private_ok: true }
    limits:
      first_byte_timeout: 120s  # a held (non-streamed) response arrives whole

default: deny

rules:
  - id: claude-api
    when: host == "api.anthropic.com"
    then: allow

  - id: claude-sign-in
    when: host in ["claude.ai", "claude.com", "platform.claude.com"]
    then: allow
```

The full policy is [`roxy.yaml`](https://github.com/roxy-proxy/roxy-proxy/blob/main/examples/quickstart/roxy.yaml).

### The denylist

The sentinel runs `deny_regex` from [`policies.py`](https://github.com/roxy-proxy/roxy-proxy/blob/main/examples/quickstart/sentinel/policies.py). It searches `<tool name> <arguments as JSON>` for a regular expression. The default catches `curl`, `wget`, `nc`, `ssh`, `scp`, `rsync` and `rm -rf`. Set your own with `SENTINEL_DENY`:

```sh
SENTINEL_DENY='\bgit\s+push\b|\bnpm\s+publish\b' docker compose up -d --wait
```

Any inspect_sentinel monitor or protocol works in its place, including ones that ask a model: set `SENTINEL` to its `module:attribute`, and for one that asks a model, `SENTINEL_MONITOR_MODEL` and a route out (add the `sentinel` service to the `egress` network). The sidecar is in [`sentinel/`](https://github.com/roxy-proxy/roxy-proxy/tree/main/examples/quickstart/sentinel).

### What a blocked call looks like

A response with a blocked tool call reaches Claude Code as an ordinary assistant message that ends the turn, not as an API error. The sentinel holds each streamed response until it has judged it. It sends the start of the response and keep-alive pings at once, so Claude Code doesn't time out, and the content arrives in one burst rather than token by token.

### This is not containment

Claude Code follows `HTTPS_PROXY` because it chooses to. The commands it runs inherit the variable, but any process can ignore it. This quickstart shows what roxy and the sentinel decide, not a boundary. To contain an agent, run it where its only route out is roxy: see [containing a workload](/deploy/overview).
