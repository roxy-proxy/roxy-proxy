# CI jobs

A CI job runs whatever its dependencies run: install scripts, build scripts, test fixtures. Any of them can try to send your source or your tokens somewhere. Put roxy in front of the job. It gets read-only access to the registries it needs, a byte budget for the one place it may upload, and nothing else.

## A starting policy

```yaml
version: 1
default: deny

listeners:
  - name: proxy
    bind: 0.0.0.0:3128

tls:
  ca_dir: /var/lib/roxy/ca

secrets:
  artifacts: { file: /run/secrets/artifact_token }

metrics:
  - id: artifact_bytes
    count: request_bytes
    where: host == "artifacts.example.com"
    window: 1h

rules:
  - id: registries
    when: >-
      method in [GET, HEAD] and (
        host == "registry.npmjs.org" or
        host == "pypi.org" or host == "files.pythonhosted.org" or
        host == "index.crates.io" or host == "static.crates.io" or
        host under "github.com" or host under "githubusercontent.com"
      )
    then: allow

  - id: artifact-upload
    when: host == "artifacts.example.com" and method == PUT and path starts_with "/builds/"
    then:
      - set_header: { authorization: "Bearer ${secret:artifacts}" }
      - allow

  - id: artifact-budget                    # watches: stops the upload that crosses it
    when: metric.artifact_bytes > 2gb
    then: { deny: { status: 507 } }
```

What each part does:

- **`registries`** allows reads from npm, PyPI, crates.io and GitHub. A `POST` to any of them is denied, so a compromised dependency can't publish or open issues with a token it found.
- **`artifact-upload`** allows one host, one method and one path prefix. roxy attaches the upload token, so the job's environment doesn't hold it.
- **`artifact-budget`** counts request bytes to the artifact host over a sliding hour. It reads a byte metric, so it keeps checking as each upload streams, and stops the upload that crosses 2 GiB.

Anything else, such as a paste site, a webhook or an IP literal, gets a `403` with `_default` in the flow log.

Try it without a build:

```sh
roxy rule test --config roxy.yaml GET https://registry.npmjs.org/left-pad
roxy rule test --config roxy.yaml POST https://registry.npmjs.org/-/user/org.couchdb.user:x
roxy rule test --config roxy.yaml --metric artifact_bytes=3000000000 --body-bytes 1024 \
  PUT https://artifacts.example.com/builds/42.tar
```

`rule test` exits 0 on allow and 3 on deny, so you can run these in CI to check policy changes.

## Containing the job

The job needs no route out except through roxy. Run it in a container on a network with no route out (`internal: true` in Docker, or a network policy that only reaches roxy), with roxy on that network and one with a route out. [Containing a workload](/deploy/overview) shows the layout. Then set the proxy variables and trust roxy's CA in the job:

```sh
export HTTP_PROXY=http://roxy:3128 HTTPS_PROXY=http://roxy:3128
export http_proxy=$HTTP_PROXY https_proxy=$HTTPS_PROXY
export SSL_CERT_FILE=/path/roxy-ca.pem          # OpenSSL, Python ssl, Go
export REQUESTS_CA_BUNDLE=/path/roxy-ca.pem     # pip
export NODE_EXTRA_CA_CERTS=/path/roxy-ca.pem    # npm
export CARGO_HTTP_CAINFO=/path/roxy-ca.pem      # cargo
```

Don't put external hosts in `NO_PROXY`: those requests would try to go direct and fail.

## Sizing the allow list

Most builds need more hosts than you expect. Run the job once with `default: allow` and a log, then read off what it reached:

```sh
jq -r 'select(.event == "request") | .req.host' flow.jsonl | sort | uniq -c | sort -rn
```

Turn the hosts you want into rules, set `default: deny` again, and run the job to confirm. Run that first pass somewhere with nothing to steal.

## Keeping a record

Every exchange is a JSON line: method, host, path, status, bytes, timing and the rule that decided. Set `log.flow.path` to write it to a file and ship it with the build's artifacts. For a closer look, `capture` tees chosen exchanges to disk. See [flow log and capture](/operate/flow-log).
