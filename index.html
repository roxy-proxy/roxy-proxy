roxy

Overview

roxy is a strict, programmable HTTP firewall. Every request and response streams through a pipeline you compose: addons that can rewrite, withhold, answer or block, then rules that judge exactly what they pass on. Run it as an egress proxy for a workload you don't trust, or as a gateway in front of the APIs your clients call.

Every exchange takes the same path: roxy parses it, the addons see it, the rules judge it, and the connector dials the upstream (how roxy works). It fails closed: anything roxy cannot parse, verify or classify is denied.

Use cases

Sandbox containment. An untrusted workload has no route out except through roxy. It points HTTPS_PROXY at roxy's proxy port and trusts roxy's CA; roxy decrypts each request, judges it, injects the credentials the workload never sees, and logs every decision. The network does the containing; roxy decides what gets out (sandbox containment).

HTTP gateway. Clients address roxy directly, as anthropic.gw.example.com behind a load balancer that terminates TLS. Rules route each request by host and inject the real API keys, so clients hold placeholders; client authentication is an addon. It governs the traffic sent to it; it is not containment (HTTP gateway).

Try it

The quickstart sends generated traffic through roxy with an auth gate, a per-user token quota and an inspect_sentinel sidecar, with roxy in node mode leasing its policy from a minimal control plane. Nothing in it needs an API key.

examples/human-approval puts a person in the loop instead: Claude Code behind roxy, with every tool call held at the proxy until someone clicks Approve or Deny in the browser.
